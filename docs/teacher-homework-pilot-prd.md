# 六年级数学提分系统 · 教师端作业与学情需求

## 1. 目标与试点范围

帮助及格线以下的学生补回基础分，尽可能达到及格。帮助刚过线的学生巩固薄弱点，在后续难度可比的测验中稳定发挥。教师能够及时反馈、安排针对性训练，并少做重复拍照、核对和录入。

首轮由一位老师、四名学生试用。学生照常交纸质练习册，在纸上订正、补练和复测。教师用手机采集作业，在工作台批改和管理学情。学生无需手机、账号或独立页面。试点用学生姓名和一份已知来源的基线成绩建立档案，再跟踪后续真实测验成绩。

## 2. 工作台与现有模块

现有导航是「今日、学生、录错、巩固单、母题库」。当前批量作业队列在「录错」的拍照批改页，手机上传入口目前一次处理一张。先在现有入口完善作业链路，试点后再评估导航合并。

| 建议入口 | 整合现有能力 | 老师在这里做什么 |
| --- | --- | --- |
| 教学工作台 | 今日、录错、批次待处理 | 收作业、看批改结果、集中核对异常、生成纸质订正清单、查看待复测 |
| 学生档案 | 学生、个性巩固和验收 | 看基线及最近成绩、具体错法和原题，跟踪订正与复测，从薄弱点发起练习 |
| 母题库 | 母题、历年原题 | 按考点找同类题，从档案跳转查看原题与来源 |

原有考试录错、批量出卷、打印和验收继续可用。日常默认进入教师工作台。

## 3. 老师每天如何使用

1. **建作业批次。** 老师选班级、日期和作业，例如「家庭作业 · 某版练习册第 40 页」。每个学生只建一份提交记录，一份记录可包含多页，同一天的课堂练习和家庭作业可分批收。
2. **四份一起上传。** 老师在手机上打开固定的教师上传页，用手机自带相机拍完，再从相册多选一次提交。电脑入口使用的二维码可以带本次作业信息。教师也可从登录后的固定入口选批次。第一版沿用手机相机和批量上传，网页内连续拍摄在试点后再评估。
3. **每张照片自动归属。** 老师首次将一张可重复使用的二维码卡绑定到一名学生，卡随练习册放置。每次拍完整单页时，把页边的二维码一起拍进去。Python 后端从同一张照片读卡号，查本班学生与卡号的绑定，再归入该生这次作业。纸上码仅用于识别归属。相片顺序可以打乱。无有效码、有多个码或不在本批名单的照片放入「待归属」，老师集中纠正。
4. **先收件，再批改。** 照片和收件结果保存后即可继续拍，教师能看见四人中谁已收到、谁缺交、哪页需要补拍。逐张后台批改，单张失败不影响其余照片。图片本身拍糊或缺页时提示补拍。图片清楚但笔迹难辨时保留原图和未判状态。已保存的图片可独立重试识别。
5. **核对一次，结果复用。** 教师把原图局部、学生作答、参考答案和批改建议放在同一处看。可一键改判、有疑问时暂缓，一次确认多条。确认后的结果同时供错题、订正和学情使用。老师若从纸本就能判断漏识别的题，可只选题号和正误，作为异常兜底。
6. **学生收到可执行的反馈。** 老师按学生生成一份订正清单，发练习册时口头说清楚，也可集中打印小条。每条标出题号和要检查的一步，例如「第 2 题第 2 小问，除了弧线，再看半圆的直边算进去没有」。学生纸上订正。老师过几天用换了数字或情境的同类题复测，记录能否独立做对。

拍照建议用后置相机竖拍完整单页，摊平练习册，让编号卡露在页边。教辅有双栏和插图时，需拍到题号、小问、图形和作答区。以后批量扫描散页时可用二维码分隔卡或逐页码，继续写入同一套作业记录。

## 4. 原题与参考答案

教师可以先拍学生作业。若作业照片里有完整印刷题干，可先由腾讯云输出批改建议。若学生只在另一本本子上写算式和答案，先给该批选择系统里的确切原题，或上传一份原题，让题号和作答可对应。

有现成答案时，教师在作业批次中绑定一次，同版同页复用。来源可以是已核对的题库答案、教辅答案页，或老师录入的答案。答案页可提取为按题号保存的答案表，第一次校对版次、题号、分数、小数、单位和答题要求。系统记住来源，识别结果与教师确认后的答案分开保存。

普通文字识别返回文字和位置。腾讯云试题批改服务能给出正误和解析，也支持提交单题参考题干和答案，或提交一张含正确解析的参考试卷图。后端需要在发起每份作业的批改时，主动带上已绑定的参考材料。先单独上传一次答案，并不会让腾讯云自动记住后续哪份作业要用它。四位学生分别提交批改任务，共用同一份参考材料。

对可按规则比对的简单题，可在校对好标准答案后由后端核对，例如题目允许等值答案时，二分之一和零点五等值。涉及步骤、图形或多种解法的题，由批改模型给建议，教师核对疑点。来源与结论无法核实时保留待确认。

## 5. 腾讯云回包与二次识别

### 5.1 先修正回包处理

本次讨论中核对到的部署代码按旧预期读取任务状态和题目列表。腾讯云文档和服务器安装的 SDK 使用的任务完成状态为 DONE，整题结构在 QuestionInfo 中，查询示例也有 MarkInfos 和手写区域信息。开发时先用去除身份信息的测试图取一份真实回包，按结果适配状态、整题与小问、手写文本与位置、正误、答案解析和知识点。开启深度模型的非快速模式时，读取可用的题目级批改置信度。

置信度是腾讯对整题判定的把握，不能直接当作某个数字的清晰度。必需字段缺失、结果为空、任务失败和超时都进入待处理。生产中禁止以固定演示题替代失败结果，也禁止把缺失的正误默认为正确。可以对照预期题号和小问清单定位漏读。腾讯做了图像矫正时，按返回坐标对应的图裁切，避免框到相邻答案。

### 5.2 局部复读是待验证项

如果首次结果的置信度偏低、漏小问、手写作答字段为空或读法相互冲突，后端可以只裁出该题或手写区域，用第二路重读。实际空白、拍摄缺损和有笔迹但没读出要分开标记。第二路先转写可见笔迹，再与参考答案比对，读不清时保留未知。切图去掉学生姓名和二维码。

是否调用支持图片的 DeepSeek Flash，保留为试点决策。先在人工作答对照下比较三种结果：腾讯整页批改、腾讯对同一张切图重读、DeepSeek 对同一张切图重读。比较实际读对多少、引入的新误读、尚需人工处理的题数和教师总用时。第二路结果冲突或依然看不清时，教师只看局部。读法一致也要通过样本抽查验证。此项不作为第一版上线前置条件。

## 6. 学生档案与错因标签

### 6.1 记录内容

一条可追溯的错题至少包含学生、日期、作业批次、题号和小问、考点、具体错法、作答原图或关键算式、参考答案来源及确认状态。首次订正和后续同类题复测分别记录。改判时更新订正清单和学情统计，可查旧结论。未发布、未判和识别模糊的结果不计入确认错题和薄弱点。

档案从近期不同作业中的同类已确认错误识别薄弱点。先处理一两个能带回基础分的考点。刚过线学生优先复测补过的考点。一次作业做对可记为「本次通过」，稳定与否看之后的独立同类题和难度可比的测验。日常练习正确率与正式测验成绩分开呈现。

### 6.2 标签怎样生成

学校先定义希望长期追踪的错因清单。腾讯云返回作答、判定、解析和可能的知识点。公开接口未见自定义错因枚举入参。后端按学校的标签表整理这些证据。规则明确的情况直接匹配。难以归类的情况可由模型从候选标签中推荐，教师仅核对疑点。模型应允许「错因待确认」，并附支持判断的一段算式或原图区域。第一版移除原有对错题默认标记「计算粗心」的做法。

| 考点 | 详细错因标签示例 |
| --- | --- |
| 圆的周长 | 半圆周长漏加直径、半径当直径代入、跑道直线段只算一条、彩带长度漏加接头 |
| 分数计算 | 通分后分子没变、分数加减时把分母也相加、除以分数时没乘倒数、乘法分配律漏乘一项 |
| 分数应用 | 找错单位「1」、把剩余量当用去量、已知部分量求总量却用了乘法 |
| 百分数应用 | 求增长率除以变化后的量、把增加量当增加后的总量、求原价却用了乘法 |
| 按比分配 | 把一项当成总份数、长宽比分配前没有把周长除以二、比的两个对象分反 |

跨题型也可记录「抄错题目数字」「漏写单位」「把面积单位写成长度单位」。看不出作答过程时，不推断学生不细心。比如同一道半圆题归为「考点：半圆周长，错因：漏加直径」，老师可以直接找到该错法对应的基础练习。

## 7. 母题库与训练的关系

历年原题保留年份、页码、题号、小问和附图。2016、2017、2020、2022 年四套真题全量导入、逐题分类，保留重复考点的不同年份出处。母题以解题方法组织，可关联多道原题。选练习时按薄弱点匹配已审核的同类题，优先选择适合当前学生的基础题。

教师发布母题后，列表和搜索直接可见，刷新仍能查看，并能从母题跳到关联原题。真题库工作可与四人作业试点并行开展。作业批改、确认和反馈应能用现有题库和教师指定题目继续运行。

## 8. 实施顺序与验收

| 阶段 | 要交付的能力 | 验收动作 |
| --- | --- | --- |
| 一：收作业和批改 | 手机多选、二维码绑定、收件和重试、真实腾讯回包、集中确认、纸质订正清单 | 用四份测试作业打乱顺序上传，四名学生各归对。补测缺码、重复上传、单张失败及老师改判。教师确认后的反馈和档案一致 |
| 二：学情与复测 | 细错因、原图依据、薄弱点推荐、按考点选题和纸质复测 | 用一次半圆周长漏加直径的例子，完成从原作业、订正、选题到复测的追踪。改判后统计更新 |
| 三：按实测扩展 | 局部二次识别、网页内连拍、更大批量收件或扫描 | 每项单独测教师总用时、归属错误、漏题、误判和未决数。观察哪些环节确实减轻核对 |

建议先试两周，与原来手批相比，记录从收件、拍照到发反馈的教师总耗时、错绑和漏题、教师需要改判的数量、学生能否看懂并完成订正和复测。对可解释的错因抽查实际依据。首轮样本用于验证流程和工作量。能否达到或稳定及格，随后用难度可比的实际测验持续判断。

所有入口只针对教师使用。二维码不能充当查看别人作业的授权凭证。原图、学生档案和答案文件按权限访问，开发及测试尽量使用去掉身份信息的作业副本。教师端核心流程可独立运行，DeepSeek API 为可选辅助，DeepSeek Harness 不作为依赖。
